FastSync

Your cloud folders, synced both ways, on Linux. Light and fast.

GitHub · Releases

Early version. Tested on Linux Mint Cinnamon. Back up what matters before you trust it with it.

What it does

Pick a folder, log in through your browser, and its files stay in sync both ways and available offline. FastSync decides what changed itself and uses rclone only to log in and move the bytes. Written in Rust with Slint, software rendering only, no async runtime.

Dropbox, Drive, OneDrive, MEGASeveral accounts at once, each with its own folder.
InstantLocal edits through inotify; cloud edits through each service's change feed, without listing the whole tree again.
Conflicts keep bothIf both sides changed a file you get name (conflict date).ext.
Safe deletesRemoved files go to a trash folder, and a run that would delete too much stops and asks.
TrayStatus, Sync now, Pause and Open folder; syncing goes on when the window is closed.

Install with Flatpak (updates itself)

This remote keeps FastSync updated with flatpak update and your software centre:

flatpak remote-add --system --if-not-exists fastsync https://evandro777.github.io/FastSync/fastsync.flatpakrepo
flatpak install --system fastsync io.github.evandro777.FastSync

Use --system: Linux Mint's Update Manager only looks at system-wide Flatpaks. The runtime comes from Flathub. The remote is GPG-signed, but the key lives in the source repository, so it is only as trustworthy as that.

Or the AppImage

Download FastSync-<version>-x86_64.AppImage from the latest release, chmod +x it and run it. It uses the fontconfig, xkbcommon and X11 libraries already on your system, and carries update information, so AppImageUpdate, Gear Lever or AppManager download only what changed.

Run one of the two, not both: they use different data folders.
